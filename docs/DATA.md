# Data

Every layer in this build is made from files inside the project; nothing is downloaded. The only terrain in the
project is a **synthetic test fixture**, so all terrain numbers are **SYNTHETIC**. Source URLs below are references for
a future manual download.

## Moving to real data

1. **MOLA tiles** (≈260 MB): put them in `data/raw/` and run `python run.py --rebuild`. Terrain turns VERIFIED,
   slope/hillshade DERIVED, interpolated grids APPROXIMATE, the red SYNTHETIC banner disappears.
2. **CTX DEM + orthomosaic:** add a GeoTIFF reader (e.g. rasterio + pyproj), reproject/clip to the region grid, then
   compare CTX vs MOLA only where both real rasters exist. Until then, nothing may be called CTX.
3. **Perseverance traverse JSON:** drop it in `data/raw/m20/`; it is read automatically (geometry only). To show a
   sol range, first open the real file, find the property that holds the sol number, and set `PATH_SOL_PROPERTY`.
4. **CRISM product + readme:** write the class table from the readme (values → names) before any display.
5. **MEDA bundle:** read column names and units from the `.xml` labels before any summary.

After loading real MOLA, before presenting: check that the header badge reads **NASA PDS · MOLA**, check the
western delta front marker (QGIS steps below), run the Demo Mission once to confirm the three routes differ and the WHY
numbers look physically sensible, re-run `pytest`, and run `python scripts/build_snapshot.py` to refresh the
no-backend fallback.

## MOLA MEGDR facts

- Archive: PDS Geosciences Node, bundle `mgs_mola_topography_derived`, collection `meg128`; PDS3 data set `MGS-M-MOLA-5-MEGDR-L3-V1.0`.
- MEGDRs exist at 4, 16, 32, 64, 128 px/deg; 128 px/deg is tiled. Simple cylindrical, planetocentric, east-positive; binned nadir shots Feb 1999 – Jun 2001.
- Tile `megt44n045hb` = topography, 44°N–0°, 45°E–90°E (contains Jezero).
- `backend/tests/data/megr44s090hb.lbl` is the text of a real MEGDR label (a different tile); a test checks the parser against it.

## Region

Jezero crater, ROI 17.85–18.90°N, 76.95–78.20°E (136 × 161 cells at 1/128°; 544 × 644 at 1/512°; 1088 × 1288 at 1/1024°).
Reference point: Octavia E. Butler Landing, 18.4447°N 77.4508°E.

## Harmonization (what the pipeline does)

1. Parse PDS3 label → 2. validate file size and extents → 3. keep the native simple-cylindrical frame →
4. clip to whole source pixels (values unchanged) → 5. verify the shot-count grid is aligned →
6. build 1/512° and 1/1024° grids by cubic interpolation (8-cell odd-reflection edge padding), shot counts by
nearest neighbour; relief window scaled to keep a ~1.4 km footprint → 7. record every step in provenance.

## How to check the delta-front point in QGIS (do this before presenting it)

The point stays **APPROXIMATE** at 18.465°N, 77.415°E. It has not been checked against real data: the only local
terrain is synthetic, and its fan-shaped bump is generated by `make_fixture.py`, so it is not evidence.

1. Install QGIS (free) from qgis.org. Open it.
2. Drag the real **CTX orthomosaic** (or a MOLA hillshade built after `fetch_mola.py`) into the QGIS window.
3. Menu **Layer → Add Layer → Add Delimited Text Layer**. Make a small CSV with one line: `name,lat,lon` and
   `delta_front,18.465,77.415`. Choose X = lon, Y = lat. Set the layer CRS to the same Mars CRS as the image.
4. Zoom to the point. **What you should see:** the point should sit at the steep front edge of the fan-shaped delta,
   west of the landing site. If it is clearly off, read the correct lat/lon with the **Identify** tool.
5. Put the new numbers in `data/targets/jezero_targets.json`. Keep `"status": "APPROXIMATE"` and write in `source`
   which image you used. Then run `python run.py --rebuild`.
