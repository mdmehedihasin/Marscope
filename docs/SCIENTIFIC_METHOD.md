# Scientific method and data integrity

## Status vocabulary (shown in the UI on every layer, target, grid and brief line)

| Status | Meaning |
|---|---|
| **VERIFIED** | Local copy of an identified official source (file present, identity checked), values unchanged |
| **DERIVED** | Calculated by a documented method from identified inputs |
| **APPROXIMATE** | Interpretation, placement or interpolation — not a surveyed or measured value |
| **ASSUMPTION** | Configurable parameter not established by any source |
| **SYNTHETIC** | Generated by MARSCOPE (test fixture or illustration) — NOT NASA data |
| **CONCEPTUAL** | Planned feature or schematic placeholder, no data behind it |
| **DATA_UNAVAILABLE** | Needs a source file that is not present in this build |

A status can only be as strong as its weakest input: anything computed from the synthetic fixture is SYNTHETIC.
Nothing interpolated is ever VERIFIED.

## This build's data situation

The only local terrain is the synthetic fixture. All terrain, slope, cost, surface and route numbers are therefore
**method demonstrations**, not statements about Mars. The red banner, the header badge, every chip and the brief say so.

## Terrain grids and resolution

- **Native grid** 1/128° (~463 m N-S). **Routing grid** 1/512° (~116 m) and **analysis grid** 1/1024° (~58 m) are made
  by cubic-spline interpolation (`scipy.ndimage.map_coordinates`, order 3, prefilter on, 8-cell odd-reflection padding
  so that a plane is reproduced exactly — unit-tested). Shot counts use nearest neighbour.
- **Finer grid spacing does not create finer source information.** The effective resolution stays ~463 m. The finer
  grids only give smoother route geometry and denser sampling of the same surface.

## Slope and why it changes with resolution

Slope = atan(|∇z|) with central differences (one-sided at edges) and latitude-dependent dx = dy·cos(lat). Central
differences span two cells, so the baseline is ~926 m on the native grid, ~232 m on the routing grid, ~116 m on the
analysis grid. Slope numbers change with spacing because:
1. a longer baseline averages short steep steps away (real data would show *higher* slopes at finer real resolution);
2. on interpolated grids, the spline can **overshoot** at sharp breaks (and the fixture has 6 m random noise), which
   raises the maximum without any new information.

| grid (synthetic fixture) | mean | p95 | p99 | max | cells > 25° |
|---|---|---|---|---|---|
| native 1/128° | 3.08° | 10.63° | 12.26° | 20.45° | 0 |
| routing 1/512° | 3.53° | 10.97° | 13.15° | 25.88° | 6 |
| analysis 1/1024° | 3.57° | 11.00° | 13.25° | 26.27° | 29 |

Compare slopes only at the same spacing. The validated plane test (10° plane → 10.000° on both native and routing grids)
shows the method is exact where the surface is smooth.

## SURFACE layer

Shaded relief (hillshade, az 315°, alt 45°, 3× vertical exaggeration) of the 1/1024° elevation grid. It is the same
elevation shown as light and shadow — **not an orbital photograph, not CTX or HiRISE, and it adds no new evidence.**

## Targets

- Landing site and crater centre: published coordinates cited in `data/targets/jezero_targets.json`. No local source
  file → **APPROXIMATE** (not VERIFIED) in this build.
- **Western delta front: APPROXIMATE, not refined.** The synthetic terrain carries no evidence about the real delta;
  the fixture's fan bump is generated, so using it would be circular. QGIS check steps: [DATA.md](DATA.md).
- West rim crest: highest point along an azimuth — DERIVED on real MOLA, SYNTHETIC here.

## Perseverance path

No local path file → only an optional **"Synthetic illustrative path — not rover data"** (deterministic sine wave in
the north of the map, > 15 km from the landing site, no metrics). A future local GeoJSON copy is read as geometry only;
its coordinate convention is checked against Butler Landing (18.4447°N, 77.4508°E); the in-region length share is
reported; any metrics would be descriptive consistency checks, never proof of safety or accuracy.

## CRISM, MEDA, global

- **CRISM:** the third-party CRISM-derived product is not present → DATA_UNAVAILABLE. No mineral classes, no mineral
  map, no "detections". The science field S still uses candidate targets only (unchanged method). When the file and its
  readme are available, classes must be mapped exactly as documented, resampled nearest-neighbour to the routing grid,
  shown as "spectral class from a third-party CRISM-derived product", and the target-only method kept switchable.
- **MEDA:** no files → CONCEPTUAL. No temperature, pressure, wind or sol range is shown.
- **Global:** no local basemap → schematic globe, CONCEPTUAL.

## Not claimed

Safety, survivability, traversability guarantees, mineral detections, real-time conditions, rover capability, model
accuracy, or agreement with any absent dataset. Interpolated or generated data are never called an accurate substitute.
